PROJECT OVERVIEW:
InsureFlow is an enterprise multi-tenant insurance enrollment, campaign management,
and operations platform. The React frontend is completely built and connects to
the backend API under `/api`.
Currently, the backend was implemented in Node.js/Express (`backend/server.js` and
`backend/billing-worker.js`).
TASK: Port the entire Node.js backend to a clean, idiomatic Java Spring Boot 3 backend
without breaking ANY existing endpoint contract, request/response JSON structure,
status code, authentication header, or database schema.

1. GLOBAL CONFIGURATION & PORTS
--------------------------------------------------------------------------------
- Server Port: 8080 (Context Path: `/api` or server root with `/api` mappings)
  NOTE: Frontend fetch calls use `/api/...` (e.g. `/api/auth/login`, `/api/admin/clients`).
  Either configure:
    server.port=8080
    (or server.servlet.context-path=/api if controllers don't include /api prefix)
- Database: PostgreSQL (Port: 5433 or 5432 via application.properties)
    spring.datasource.url=jdbc:postgresql://localhost:5433/insureflow
    spring.datasource.username=insureflow_user
    spring.datasource.password=your_db_password
- CORS:
    Allow origins: http://localhost:5173, http://localhost:3000 (React Vite app)
    Allowed methods: GET, POST, PUT, PATCH, DELETE, OPTIONS
    Allowed headers: *
    Allow credentials: true

2. DATABASE SCHEMA (POSTGRESQL + FLYWAY)
--------------------------------------------------------------------------------
PostgreSQL extension: `uuid-ossp`
Primary Keys: UUID throughout all tables.

Tables:
1. `users`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - email VARCHAR(255) UNIQUE NOT NULL
   - password_hash VARCHAR(255) NOT NULL
   - first_name VARCHAR(100) NOT NULL
   - last_name VARCHAR(100) NOT NULL
   - date_of_birth DATE
   - phone VARCHAR(30)
   - role VARCHAR(30) NOT NULL DEFAULT 'CUSTOMER'  ('CUSTOMER', 'ADMIN', 'OPERATIONS')
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
   - updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

2. `clients` (Banks / Institutions)
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - name VARCHAR(255) NOT NULL
   - code VARCHAR(50) UNIQUE NOT NULL
   - contact_email VARCHAR(255)
   - is_active BOOLEAN DEFAULT TRUE
   - business_type VARCHAR(100) DEFAULT 'Bank'
   - status VARCHAR(30) DEFAULT 'A-ACTIVE'
   - address TEXT
   - state VARCHAR(100)
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

3. `products`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - name VARCHAR(255) NOT NULL
   - code VARCHAR(10) UNIQUE NOT NULL ('DD' for AD&D, 'HP', 'RC')
   - description TEXT
   - status VARCHAR(30) NOT NULL DEFAULT 'ACTIVE'
   - free_basic_enabled BOOLEAN DEFAULT FALSE
   - free_basic_min DECIMAL(12, 2) DEFAULT 0.00
   - free_basic_max DECIMAL(12, 2) DEFAULT 0.00
   - premium_rate_per_thousand DECIMAL(6, 2) DEFAULT 0.60
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

4. `campaigns`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - client_id UUID REFERENCES clients(id) ON DELETE CASCADE
   - product_id UUID REFERENCES products(id) ON DELETE CASCADE
   - campaign_id VARCHAR(100) UNIQUE NOT NULL (e.g. CAMP-XXXXXX)
   - name VARCHAR(255) NOT NULL
   - description TEXT
   - status VARCHAR(30) NOT NULL DEFAULT 'PLANNED' ('PLANNED', 'ACTIVE', 'INACTIVE')
   - start_date DATE
   - end_date DATE
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

5. `campaign_events`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - campaign_id UUID REFERENCES campaigns(id) ON DELETE CASCADE
   - event_id VARCHAR(100) UNIQUE NOT NULL (e.g. EVT-XXXXXX)
   - channel VARCHAR(50) NOT NULL ('Telemarketting', 'Banner', 'Collection', 'Letter', 'NewsLetter')
   - media VARCHAR(50) DEFAULT 'direct mail'
   - send_date DATE
   - quantity INT DEFAULT 0
   - event_type VARCHAR(100) DEFAULT 'mailing'
   - final_description TEXT
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

6. `segments`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - event_id UUID REFERENCES campaign_events(id) ON DELETE CASCADE
   - client_id UUID REFERENCES clients(id) ON DELETE CASCADE
   - name VARCHAR(255) NOT NULL
   - spoken_key VARCHAR(100) NOT NULL (Format: {insuranceStatus}-{clientCode}-{stateCode}, e.g. UI-APEX-TX)
   - insurance_status VARCHAR(10) NOT NULL ('I' for Insured, 'UI' for Uninsured)
   - state VARCHAR(50) NOT NULL
   - target_count INT DEFAULT 0
   - description TEXT
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

7. `campaign_codes`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - campaign_id UUID REFERENCES campaigns(id) ON DELETE CASCADE
   - code VARCHAR(100) UNIQUE NOT NULL
   - is_used BOOLEAN DEFAULT FALSE
   - used_by_user_id UUID REFERENCES users(id) ON DELETE SET NULL
   - used_at TIMESTAMPTZ
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

8. `policies`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE
   - product_id UUID NOT NULL REFERENCES products(id) ON DELETE RESTRICT
   - campaign_code_id UUID REFERENCES campaign_codes(id) ON DELETE SET NULL
   - policy_number VARCHAR(100) UNIQUE NOT NULL (e.g. POL-YYYY-XXXXX)
   - cover_amount DECIMAL(12, 2) NOT NULL
   - monthly_premium DECIMAL(10, 2) NOT NULL ((coverAmount / 1000) * 0.60)
   - status VARCHAR(30) NOT NULL DEFAULT 'ACTIVE' ('ACTIVE', 'CANCELLED', 'LAPSED')
   - effective_date DATE NOT NULL DEFAULT CURRENT_DATE
   - cancellation_date DATE
   - cancellation_reason VARCHAR(255)
   - address_line1 VARCHAR(255) NOT NULL
   - address_line2 VARCHAR(255)
   - city VARCHAR(100) NOT NULL
   - state VARCHAR(50) NOT NULL
   - zip_code VARCHAR(20) NOT NULL
   - certificate_s3_key VARCHAR(255)
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
   - updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

9. `beneficiaries`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - policy_id UUID NOT NULL REFERENCES policies(id) ON DELETE CASCADE
   - first_name VARCHAR(100) NOT NULL
   - last_name VARCHAR(100) NOT NULL
   - relationship VARCHAR(50) NOT NULL
   - percentage DECIMAL(5, 2) NOT NULL
   - phone VARCHAR(30)
   - is_primary BOOLEAN DEFAULT TRUE
   - guardian_name VARCHAR(100)
   - is_active BOOLEAN DEFAULT TRUE
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

10. `policy_audit_logs`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - policy_id UUID NOT NULL REFERENCES policies(id) ON DELETE CASCADE
   - changed_by_user_id UUID REFERENCES users(id) ON DELETE SET NULL
   - action VARCHAR(100) NOT NULL
   - old_value JSONB
   - new_value JSONB
   - changed_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

11. `claims`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - policy_id UUID NOT NULL REFERENCES policies(id) ON DELETE CASCADE
   - user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE
   - claim_number VARCHAR(100) UNIQUE NOT NULL (e.g. CLM-YYYY-XXXXXX)
   - incident_type VARCHAR(100) NOT NULL
   - incident_date DATE NOT NULL
   - description TEXT
   - status VARCHAR(30) NOT NULL DEFAULT 'SUBMITTED' ('SUBMITTED', 'UNDER_REVIEW', 'APPROVED', 'REJECTED')
   - claimed_amount DECIMAL(12, 2) NOT NULL
   - approved_amount DECIMAL(12, 2)
   - reviewer_notes TEXT
   - reviewed_by UUID REFERENCES users(id) ON DELETE SET NULL
   - reviewed_at TIMESTAMPTZ
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
   - updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

12. `claim_documents`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - claim_id UUID NOT NULL REFERENCES claims(id) ON DELETE CASCADE
   - file_name VARCHAR(255) NOT NULL
   - s3_key VARCHAR(255) NOT NULL
   - content_type VARCHAR(100)
   - file_size BIGINT
   - uploaded_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

13. `premium_records`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - policy_id UUID NOT NULL REFERENCES policies(id) ON DELETE CASCADE
   - billing_month DATE NOT NULL (first day of month, e.g. 2026-11-01)
   - amount DECIMAL(10, 2) NOT NULL
   - status VARCHAR(30) NOT NULL DEFAULT 'PENDING' ('PENDING', 'PAID', 'FAILED', 'RETRY_SCHEDULED')
   - retry_count INT DEFAULT 0
   - payment_attempt_count INT DEFAULT 0
   - last_attempted_at TIMESTAMPTZ
   - due_date TIMESTAMPTZ
   - paid_at TIMESTAMPTZ
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

14. `payment_retry_queue`
   - id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
   - premium_record_id UUID NOT NULL REFERENCES premium_records(id) ON DELETE CASCADE
   - retry_number INT NOT NULL (1, 2, or 3)
   - scheduled_at TIMESTAMPTZ NOT NULL (Day 3, Day 7, Day 14 after billing generation)
   - attempted_at TIMESTAMPTZ
   - result TEXT
   - created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP

3. AUTHENTICATION & SECURITY SPECIFICATION
--------------------------------------------------------------------------------
- Password Hashing: BCryptPasswordEncoder (strength 10 or 12).
- JWT Tokens:
  - Header: Authorization: Bearer <token>
  - Claims in token:
      {
        "id": "uuid-string",
        "email": "user@example.com",
        "role": "CUSTOMER" | "ADMIN" | "OPERATIONS",
        "firstName": "John",
        "lastName": "Doe"
      }
  - Secret: Configurable via `jwt.secret` (minimum 256-bit key for HMAC-SHA256).
  - Expiration: 24 hours.
- Roles & Access:
  - CUSTOMER: can access customer policy endpoints (`/api/policies`, `/api/claims`, `/api/enrollment/**`).
  - ADMIN, OPERATIONS: staff access to `/api/admin/**`.

5. BILLING WORKER & PAYMENT GATEWAY SCHEDULER
--------------------------------------------------------------------------------
In Spring Boot, implement this using `@Scheduled` and Spring service components:

1. `MockPaymentGateway`:
   - Simulates 70% success, 30% failure rate.
   - On success: returns `transactionId` ("TXN-timestamp-random").
   - On failure: returns failure reason ('Insufficient funds', 'Card declined by issuer',
     'Payment gateway timeout', 'Invalid account details', 'Transaction limit exceeded').

2. `BillingService`:
   - `generateMonthlyPremiumRecords(Date date)`:
     Queries all policies with `status = 'ACTIVE'`.
     Creates a `premium_records` row with `billing_month = YYYY-MM-01`, `status = 'PENDING'`,
     `due_date = month_start + 7 days`, `amount = policy.monthly_premium`.
     Skips if a record for that `policy_id` and `billing_month` already exists.
   - `processPendingCharges()`:
     Charges each PENDING record via `MockPaymentGateway`.
     If Success -> updates `status = 'PAID'`, `paid_at = NOW()`.
     If Failure -> updates `status = 'RETRY_SCHEDULED'`, creates 3 rows in `payment_retry_queue`:
       - Attempt #1: scheduled at NOW + 3 days
       - Attempt #2: scheduled at NOW + 7 days
       - Attempt #3: scheduled at NOW + 14 days
   - `processDueRetries()`:
     Finds queue entries where `scheduled_at <= NOW()` and `attempted_at IS NULL`.
     Charges record. If success, marks `PAID`. If failed 3 times (0 remaining retries),
     marks status permanently as `FAILED`. Note: Policy is NOT lapsed or suspended.

3. Spring `@Scheduled` Schedulers:
   - Monthly Billing: `@Scheduled(cron = "0 5 0 1 * ?")` (1st of every month at 00:05 AM)
   - Daily Retry Evaluation: `@Scheduled(cron = "0 0 6 * * ?")` (Every day at 06:00 AM)

6. ENTITY RELATIONSHIP DIAGRAM (JPA ENTITY MAPPINGS)
--------------------------------------------------------------------------------
- `User` 1 --- * `Policy`
- `Client` 1 --- * `Campaign`
- `Product` 1 --- * `Campaign`
- `Product` 1 --- * `Policy`
- `Campaign` 1 --- * `CampaignEvent`
- `Campaign` 1 --- * `CampaignCode`
- `CampaignEvent` 1 --- * `Segment`
- `Policy` 1 --- * `Beneficiary`
- `Policy` 1 --- * `PolicyAuditLog`
- `Policy` 1 --- * `Claim`
- `Policy` 1 --- * `PremiumRecord`
